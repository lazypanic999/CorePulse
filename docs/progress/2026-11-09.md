## Measured result and limits

The [strict cohort card](../datasets/2026-11-09-local-preview.md) documents 12 normal, five AMF and five UPF runs. Its 60 windows yielded 31 training, 20 held-out and nine purged windows. Every fault was followed by a verified ordered reset. The final post-campaign observation had N2/N4 up and 2/2 gateway replies; this is not proof of Internet access.

The scenario reference reached window macro F1 0.521 versus the majority reference's 0.190, but **missed every AMF test window**. On the separate binary task, the resource reference's 0.642 trailed the packet rule's 0.800. Wrong predictions remain visible. These results do not support live deployment or a production detection claim.

All runs share a session, node, UE and configuration. CPU source averages overlapped captures, and the original cohort omitted their timestamps/windows. A two-minute capture-time embargo mitigates proximity without certifying measurement-time independence. Newly retained metadata cannot repair historical inputs. Raw lab inputs remain local; the public card and aggregate summary are not an independently reproducible public dataset.

The downloaded v0.2.0 Windows/Linux archives passed SHA-256 verification, Windows version/dry-run worked, and the published Linux evaluator reproduced the exact frozen report bytes. Newer evaluators preserve that study's CSV and numerical results, while report limitations/grouping can change. Hosted CI covers the full Go suite, vet, lab-helper fixtures, build/dry-run and the synthetic CLI example. Native Windows/macOS jobs now supplement the Linux source-minimum job. Release publication additionally waits for actual packaged Linux amd64, Windows amd64 and macOS arm64 walkthroughs. Linux arm64 and Darwin amd64 remain cross-built rather than natively executed. Go 1.27 macOS archives require macOS 13 or later.

A separate prospective smoke test collected a verified two-sample baseline and an AMF fault with one declared session ID. The first fault checkpoint and final record retained it; five fault captures and consecutive 2/2 gateway replies did not hide the observed N2 loss, so the CLI returned 2. The ordered reset then restored N2/N4 and packet health, and `doctor` passed all eight checks. Exporting the separate records produced three session-tagged windows from 13 continuous-dashboard captures; whole-session splitting correctly refused this single-session input. This is lifecycle validation, not a new cross-session performance study, and it does not alter the frozen cohort.

Two [staged UPF recovery diagnostics](../experiments/2026-11-09-upf-recovery.md) also distinguish PFCP association from the UE packet path. They retain the sequential/timing confounds; the default reset remains unchanged. Missing ping summaries are unavailable evidence rather than measured packet loss.

## Next work

1. Diagnose source-frame reuse/age and define an explicit measurement-time policy ([#44](https://github.com/lazypanic999/CorePulse/issues/44), no-cluster contributor issue).
2. Collect genuinely separate, predeclared sessions with scenario support and a dataset card, then use the implemented whole-session holdout. The original unknown-session cohort cannot qualify retroactively ([session guide](../session-holdouts.md)).
3. Continue the UPF/PFCP restart investigation ([#22](https://github.com/lazypanic999/CorePulse/issues/22)) and collect predeclared independent cohorts after any configuration change.
4. Extend the fault catalog only with reviewed scope, durable rollback ownership and interruption tests. The [N3 loss design issue](https://github.com/lazypanic999/CorePulse/issues/57) records read-only tool/capability gaps and an explicitly directional proposal. The current injector supports AMF/UPF `pod_crash`; packet loss, latency and SCTP interruption are not implemented.

The next model comparison should use new predeclared data and retain the existing poor result. The synthetic walkthrough is a contributor tool, never a replacement for measured evidence.
